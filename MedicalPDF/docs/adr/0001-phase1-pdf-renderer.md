# ADR-0001: Phase 1 PDFレンダラーにReportLabを採用する

- 状態: Accepted for Phase 1
- 日付: 2026-07-12
- 対象: MedicalPDF Phase 1

## 背景

MedicalPDFは、固定データからA4縦・1ページの日本語PDFを安定生成し、ページ数、文字欠落、レイアウトを検証する必要があります。初期設計ではHTML/CSSとPlaywrightを候補にしていました。

Phase 1では、ブラウザーやフロントエンドを導入せず、ページ座標と描画前の高さを直接制御できる小さなプロトタイプが必要です。また、PDFをPNGへレンダリングし、機械検証と目視確認の両方を行います。

## 決定

Phase 1のPDF生成にはReportLabを使用します。

- ReportLabでA4ページ、カード、本文、出典、フッターを直接描画する
- PyPDFでページ数と用紙寸法を確認する
- PDFPlumberで必須文字列と文字座標を確認する
- PopplerでPNGへ変換して目視確認する
- レイアウト超過時は縮小・クリップせず失敗させる

## 理由

- ブラウザー実行環境を追加せずに検証できる
- 描画前に要素の高さを計測できる
- A4一枚を超える条件を明示的に失敗させられる
- Pythonだけで生成・検証処理をまとめられる
- Phase 1の固定データ検証に十分な表現力がある

## 影響

### 利点

- 小さく決定的なPhase 1実装になる
- PDF生成と検証を自動テストできる
- OSフォントまたはCIDフォントで日本語を扱える

### 制約

- HTML/CSSテンプレートを非開発者が編集する構成ではない
- 複雑な誌面やWebとのデザイン共有には追加設計が必要
- フォントの可用性を実行環境ごとに確認する必要がある

## 将来の見直し条件

次の場合は、Playwrightまたは別レンダラーを比較するADRを追加します。

- WebプレビューとPDFで同一テンプレートを共有する
- 施設ごとの高度なブランドテンプレートが必要になる
- ReportLabではアクセシブルPDF要件を満たせない
- デザイナーがHTML/CSSでテンプレートを管理する必要がある

見直し時も、A4一枚の失敗条件と生成後のPDF検証は維持します。
